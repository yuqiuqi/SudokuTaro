# SudokuTaro 自适应设计

视觉基准：[确认的 Figma 设计](https://www.figma.com/design/AhWwkAjjXti2imJAbhgrTY?node-id=20-545)。采用均衡的雾蓝与浅青色光晕、细边框悬浮棋盘、半透明玻璃工具栏与数字底座。竖屏的标题、状态、工具和数字区均与棋盘外框左右对齐。网页使用系统字体，不下载或分发 SF Pro。

## 布局策略

使用 CSS 像素，不读取设备型号或物理分辨率。先扣除浏览器可见高度与安全区，再通过 `ResizeObserver`、`visualViewport.resize` 计算棋盘尺寸。主页面不设置 ScrollView；棋盘和操作区的实际几何在浏览器测试中检查，不以隐藏滚动条作为适配证明。

| 模式 | 场景 | 排布 |
|---|---|---|
| 常规 | 竖屏、高度充足 | 棋盘 + 工具栏 + 5/4 两排数字 |
| 紧凑 | 较矮的竖屏 | 缩小留白，保留选格说明与所有操作 |
| 极短 | 可用高度不足 555 CSS px | 棋盘上置；工具横排、数字按 5/4 两排放在下方 |
| 宽屏 | 足够宽或宽高比偏宽 | 棋盘左置；工具与 3×3 数字区右置 |

常规棋盘外框上限 350px、紧凑 306px、极短 224px、宽屏 414px；这些是视觉上限，实际尺寸继续受可用高度与宽度约束。页面菜单分页展示规则；提示卡在操作区替换工具和数字，提供独立关闭按钮与「我来试试」。提示不覆盖棋盘，关闭后恢复数字区。操作反馈在棋盘外的页脚行显示并自动消失；出现较长反馈或提示时，布局预留相应高度。实际高度小于 440px、可用宽度至少 240px 时优先左右排布，以免压窄提示文字。小尺寸下格子会缩小，不能把无滚动等同于与大屏相同的触控舒适度。

折叠屏始终先按实际视口重排，保持游戏状态。浏览器若提供窗口分区几何，则额外限制棋盘尺寸和预留分区间隙；未提供分区信息时，回退为普通响应式布局。网页不能仅靠设备型号可靠判断折角或真实折痕，因此不承诺所有设备均能识别折弯区域。实际 iPhone / Safari 与折叠设备仍需真机验证。

## 输入与参与感

- 四角选中框继承棋盘外缘圆角；圆角按单格可用尺寸限幅，避免边缘裁切与极小视口下的圆角归一化。
- 所有格子与数字均为原生按钮。没有 input、textarea 或 contenteditable；手机点击不会因本游戏输入框而唤起系统键盘。
- 笔记使用每格 3×3 候选数；正式填数清理同区域候选数，撤销恢复前一次完整数字和笔记状态。
- 冲突输入只高亮相关格子，不覆盖原状态；非直接冲突的推理失误可由玩家继续检查或通过提示回看。
- 教学提示先定位、再提问、最后解释，标题和正文分别递进；回看类提示若内容相同，只展示一次并隐藏下一条操作。只展示由合法候选数推导的唯一候选/区域唯一位置；无可教的确定步时明确标记仍需继续分析，绝不直接填入答案。
- 三档题目生成时逐格验证唯一解；难度描述仅按留空数量，未声称完成专业逻辑难度评级。
- 完成单元给予轻量反馈；通关先播放从左上到右下的彩虹立体波浪，全部格子落定后立即点亮全部缝隙一次，再展示勾选奖章、真实成绩及个人纪录。庆祝由一次胜利边沿触发；刷新已完成局面不重放、不重复计数。
- 胜利布局独立于规则／设置弹窗：小屏竖屏将奖章与标题并排，低矮横屏将完成棋盘预览放在成绩左侧；徽章不因小屏而隐藏。根据实际容器高度压缩间距、保留成绩和全部操作。
- 「欣赏棋盘」收起成绩卡并把键盘焦点还给「查看成绩」，完成局面仍可重开成绩或开始新局。Escape 跳过庆祝；新局、其他菜单清理庆祝状态及偏好监听，关闭菜单后也不会冒出旧成绩。
- 遵循 `prefers-reduced-motion`，直接展示静态胜利结果；庆祝时动态启用该偏好也立即结束动效。振动仅在玩家已经启用时触发。主游戏中撤销和擦除免费。

## 彩虹胜利波浪与青柠缝隙光（v1.2.0）

原生 81 格按 `row + column` 错开 90ms；每格包络 960ms，整体 2400ms。格子随棋盘尺寸抬升 4–18px，配合倾斜、深度阴影和透明彩虹高光；28% 达到峰值、72% 落回平面，余段渐隐。动画不改变棋盘布局尺寸，数字位于高光之上。右下角最后一格的实际 `victory-wave` animationend 在同一次状态转换中启动 650ms 的单次缝隙光；不插入延时。绝对定位、无填充 SVG 用百分比线条覆盖 8 条横缝、8 条竖缝与圆角外缘，包含 3×3 宫界；窄淡亮芯、青柠发光与最多 4.5px、随棋盘缩窄的柔光线模拟缝隙向外逸出的光。只动画一个光层的透明度，格面不变色、不运动。光层 `aria-hidden` 且 `pointer-events: none`。结果仅由光层真实 `victory-seam-light` animationend 揭晓；不得恢复固定延时推断任一阶段结束。

验证时用 Web Animations API 暂停并采样初段、中段、末段和余辉，检查真实正 Z 位移、倾角、阴影、暖冷色及相邻对角线延迟。暂停最后一格超过总时长时结果仍应隐藏；恢复后应先收到末格结束事件，再进入缝隙光。再暂停缝隙光超过 650ms，确认结果继续隐藏，恢复并收到真实结束事件后才显示成绩。采样起光／峰值／衰减，检查无填充线条与真实格缝对齐、格子及数字中央样式不变、真实截图中央像素不变、光层不挡点击。对变换后的真实格子矩形与实际 `visualViewport` 比较，不能用 overflow 隐藏裁切来通过测试。结束后检查平面变换、81 格及数字按钮的真实点击。

专项覆盖 280×320、480×240、568×240 和 390×720 但实际可视高度 400px 的波形帧；保留所有既有布局和交互回归。检查庆祝中打开并提前关闭设置、立即新局、Escape、刷新和静态／动态减少动态效果，无残留动画或延迟弹窗。刷新不重播、不重复记胜场。极短横屏棋盘仍受原有可用空间限制，不能以截图可见推断触控舒适度。

2026-10-20 完整波浪与缝隙光通过类型检查、9 项逻辑测试、根路径及 Pages 子路径生产构建与完整 Chromium 浏览器测试，运行时错误为空；构建仍有原有入口体积警告。合并提交 `8fb93f3` 的主分支 CI 和 Pages 实际发布成功。系统 curl 正常 TLS 校验取得线上资源后，经本地转接由 Chromium 渲染，验证两段动效顺序、格子落平及仅缝隙发光、刷新不重复计数；未修改信任库或关闭 TLS 校验。此方式不等同于直接在线 Chromium 导航，真实 Safari 或折叠硬件仍待验证。部署证据见 [更新说明](releases/v1.2.0.md)，正式标签及发布状态见 [Releases](https://github.com/yuqiuqi/SudokuTaro/releases)。

## 验证

```bash
npm ci
npm run typecheck
npm test
npm run build:h5
npx playwright install --with-deps chromium
npm run test:browser
# GitHub Pages 子路径：
GITHUB_PAGES=true npm run build:h5
PAGES_BUILD=true npm run test:browser
```

浏览器测试自启临时静态服务器，覆盖 280×480、320×480、320×568、360×640、375×667、390×720、390×844、414×896、430×932、480×320、568×320、667×375、720×540、768×1024、844×390、1024×768。

检查每个棋盘格、数字按钮和主工具均在视口内；检查双向文档滚动、无原生文本输入、候选数和撤销、冲突拒绝、提示不自动填数、旋转/刷新保留进度、中英文规则弹窗及通关计数。

补充回归覆盖工具图标、竖屏两侧对齐、中英文三层提示不遮挡棋盘、提示关闭后恢复数字区与焦点、带图标的冲突反馈，以及 568×240、480×240 下数字 7～9 的实际点击、方向键边界，以及中英文新局、规则、设置和通关弹窗。弹窗几何检查比较实际 `visualViewport.height`，不只检查外框；竖屏可视高度压缩到 400px 时仍须显示全部操作。极短横屏将工具与数字区并排，弹窗根据实际容器高度进一步缩减留白、重排难度选项。

测试同时模拟左右分区、上下分区与浏览器工具栏压缩 `visualViewport` 的情况。模拟用于验证几何回退，不代表已经在折叠硬件上实测。

新增胜利回归覆盖中英文 280×320、280×400、280×480、320×480、390×720、390×720 但实际可视高度 400px、480×240、568×240、568×320、844×390；检查奖章保留、独立横屏棋盘、成绩卡与欣赏棋盘后的按钮边界、焦点恢复、刷新／重开及减少动态效果。独立浏览器复核还检查庆祝中打开设置、立即新局、振动偏好与动态切换减少动态效果。
